## Changes Since v0.1.44

PDF signature validation leaves the gateway, the default Content-Security-Policy lets OpenDocViewer's opt-in OCR run, and a viewer request that races its own `/prep` no longer fails.

- **Removed: server-side PDF signature validation.** The `/signatures/{sessionKey}/{fileIndex}` endpoint, its isolated worker mode and the PdfPig and System.Security.Cryptography.Pkcs runtime dependencies are gone. OpenDocViewer v2.12.0 checks PDF signature integrity in the browser from the bytes it already holds and no longer calls the gateway for it. A legacy `ODVGateway:signatures` section in `appsettings.json` is ignored, so an existing site keeps starting; the retired `--signature-worker` argument now starts the normal web host.
- **Default CSP permits WebAssembly for the viewer.** When `contentSecurityPolicy` is `null`, the default policy now includes `'wasm-unsafe-eval'` in `script-src`, which OpenDocViewer's opt-in OCR and pdf.js decoders need. It does not enable JavaScript `eval` or `new Function` and adds no script origin; the existing inline-bootstrap permission is unchanged. A site with its own `contentSecurityPolicy` must add the token itself if OCR is enabled.
- **A viewer request that races its `/prep` waits for it.** WebClient posts `/prep` and opens `?sessiondata=` at the same time, and on a busy host the viewer request could arrive before the session was stored ("Prepared ODVGateway session was not found"). The gateway now polls the session store for up to `prepHandoffWaitMilliseconds` (default 5000, capped at 30000, `0` disables) before reporting the miss, and logs `WaitedMs` on both outcomes.
- **Site configuration generator (tooling).** `tools/appsettings-generator` (PowerShell 7) builds a site `appsettings.json` from the shipped sample and a small site profile, checks an existing site file for drift after an upgrade, writes a commented starter profile, and can read the sample from a release tag. Edits are text-preserving and every result is re-read with the configuration loader's own options.
- **Code-scanning findings resolved and tests hardened.** CodeQL findings (disposal of locals, shadowed parameters, exact P/Invoke entry points, a drained truncated stream) were fixed before the signature code was removed; the test suite gained proofs for wait cancellation, resource and exception behaviour, startup with a legacy signatures block and response ownership.
- **Reproducible builds and dependencies.** Checkout line endings are pinned so the OMP artifact is byte-stable; Microsoft.AspNetCore.Mvc.Testing 10.0.14 for the tests, and the shared OMP version helpers and deterministic Razor generator are synced with OpenModulePlatform. The release still carries the CycloneDX SBOM.

## Upgrade Guidance

Upgrade v0.1.44 deployments to v0.1.45 together with OpenDocViewer v2.12.0, which no longer asks the gateway about signatures. No `appsettings.json` change is required: a `signatures` section left from v0.1.44 is ignored and can be removed at your convenience. Sites that set their own `contentSecurityPolicy` and enable OCR in the viewer add `'wasm-unsafe-eval'` to its `script-src`. `prepHandoffWaitMilliseconds` defaults to 5000; set it only to shorten or disable the wait. The .NET runtime requirement is unchanged from v0.1.44.
