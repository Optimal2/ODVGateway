## Changes Since v0.1.42

A default-policy fix that unblocks printing in the viewer, plus the dependency and test baseline.

- **The default Content-Security-Policy no longer blocks the viewer's PDF print path.** The default policy had no `frame-src`, so the hidden blob-PDF print frame fell back to `default-src 'self'` and was blocked; the viewer's cross-origin probe of the frame then threw and the user saw "Preparing print" reach 100 % and then nothing. The default now carries an explicit `frame-src 'self' blob:`. It also carries `connect-src 'self' blob:` — not for the generated PDF, which is never fetched, but for the viewer's external PDF worker, which fetches the page images' `blob:` URLs and obeys the CSP stamped on its own script response; without it the worker path degraded silently to the main thread. Reproduced and fix-verified against a simulated WebClient handoff. (OpenDocViewer v2.9.0 also stops hanging when a host policy blocks the frame, and falls back instead.)
- **Dependencies.** NLog.Web.AspNetCore 6.2.1; .NET SDK pin 10.0.400. `dotnet list package --vulnerable --include-transitive` reports no vulnerable packages.
- **Tests and CI.** Unit tests migrated from xunit v2 to xunit.v3 4.0.1 with Microsoft.NET.Test.Sdk 18.10.1; CI and CodeQL workflow actions on their latest majors; the local CI gate runs the shared-script check strictly.
- **Documentation.** README restores a 'Known limitations' section and clarifies the two archives; private companion repositories are referred to generically.

## Upgrade Guidance

Drop-in for v0.1.42 deployments that use the default policy. Two checks:

1. **Deployments that override `contentSecurityPolicy`** in configuration must add the same two sources themselves: `frame-src 'self' blob:` and `connect-src 'self' blob:`.
2. **No second CSP header.** Remove or align any `Content-Security-Policy` added by IIS (`web.config` `customHeaders`, `applicationHost.config`, URL Rewrite outbound rules) or by a reverse proxy. With two CSP headers the browser enforces the intersection, so the stricter copy wins and printing stays blocked. Verify on a viewer response that exactly one `Content-Security-Policy` header is present and that it contains `frame-src 'self' blob:`.
