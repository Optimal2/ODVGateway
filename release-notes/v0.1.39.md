## First official ODVGateway release

ODVGateway has been deployed as an OpenModulePlatform artifact since 0.1.x, but it had no official release line of its own: no tags, no published binaries, and no way to install it outside OMP without building it yourself. This release adds that.

The application code is unchanged from what OMP artifact 0.1.38 already delivered. What is new is the release process around it.

## Changes Since the 0.1.38 artifact

- Adopted the shared test standard: xUnit tests emit TRX everywhere, and the release workflow runs them rather than assuming they were run locally.
- Corrected the documented test command, which named a solution file this repository does not have.
- Added a "Running tests" section to the documentation, and stopped the local CI help text from describing this repository as private - it is public.
- Updated the test infrastructure baseline (Microsoft.NET.Test.Sdk 18.8.1, xunit.runner.visualstudio 3.1.5).

## What this release adds

- **A published archive.** `ODVGateway-vX.Y.Z.zip` contains the framework-dependent publish output, ready to deploy to an IIS host that has the ASP.NET Core hosting bundle.
- **An official version.** `Directory.Build.props` now carries `<Version>`, which is the application version and the one the binaries report. It is deliberately separate from the OMP artifact version in `omp-components.json`: an artifact-only test build can bump one without the other, and neither is forced to match.
- **A release helper.** `scripts/release.ps1` gained `-ReleaseType`, `-Yes` and `-Publish`. Without them it behaves exactly as before, as a local gate. With them it bumps the version, commits, tags, and - only with `-Publish` - pushes.

## Upgrade Guidance

No action is required for existing OMP deployments; the artifact continues to be delivered through OMP as before. Standalone deployments can now install from the published archive instead of building from source.
